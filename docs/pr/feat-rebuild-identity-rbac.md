# feat: CakePHP 5 rebuild — identity, RBAC and row-level security

## Summary

Starts the rebuild of Kualitet on CakePHP 5 in `app/` (ADR-0006), next to the legacy CakePHP 3.9 application, which stays untouched as a functional reference. This branch delivers the foundation every business module will sit on: identity, roles per development, a second factor for super-administrators, and isolation between developments enforced in PostgreSQL.

No business module (units, fees, payments, reports) is included yet.

## How to review

1. `docs/adr/ADR-0005-multi-development-rbac-design.md` (section 1 and the closing "RLS-SEC-001 implementation notes") and `docs/adr/ADR-0006-rebuild-on-cakephp5.md`.

## Deployment and setup notes

- New database: run `php bin/provision_db_roles.php --write-local` (as a PostgreSQL superuser) before the first migration.
- Migrations now run with the owner connection: `bin/cake migrations migrate -c migrations`.
- `bin/cake create_user` needs the owner login enabled; in production set `kualitet_owner` to `NOLOGIN` after the migration window.
- New environment variables: `TOTP_ENCRYPTION_KEY` (at least 32 random bytes, required in production), `COOKIE_SECURE` (default `true`; set `false` only for a local HTTP server), `BUSINESS_TIMEZONE` (default `America/Mexico_City`; changing it needs a migration for `business_today()`).
- Credentials live only in the git-ignored `app/config/app_local.php`.

## Known limits and follow-ups

- Accepted residual risks of the RLS layer are listed at the end of ADR-0005 (application-trusted `app.user_id`, job context setting, pre-authentication functions with explicit user ids, existence oracles).
- REBUILD-003-F3: static check that every routed action performs an authorization check.
- REBUILD-003-F5 and F7: minor hardening from the slice reviews.
- RLS-002: separate login role for jobs, webhook context, `audit_log`, occupancies.
- The legacy application at the repository root is unchanged.
